# 0001: Anvia Framework Stays a Dependency

**Status:** Accepted
**Date:** 2026-10-18
**Supersedes:** None

## Context

Talago started as a copy of `anvia-fullstack-app` with the same features, and the app's own names were changed from Anvia to Talago. "Anvia" is also the name of the framework the app is built on, which ships as npm packages and container images. No Talago equivalents of these exist.

## Decision

Keep every framework reference unchanged:

- npm packages `@anvia/core`, `@anvia/client`, `@anvia/server`, `@anvia/react`, `@anvia/react-ui`, `@anvia/openai`, `@anvia/lens`, and `@anvia/memory-prisma`.
- The Anvia Lens images `ghcr.io/anvia-hq/lens` and `ghcr.io/anvia-hq/lens-web`, and the "Anvia Lens" sender name, in `infra/lens/docker-compose.yaml`.
- The `--anvia-stream-reveal-*` CSS variables in `apps/web/src/styles.css`, which belong to the Anvia streaming renderer.
- The `BEGIN/END ANVIA MEMORY PRISMA 8 MODELS` markers in `packages/db/prisma/schema.prisma`, around the block generated by `@anvia/memory-prisma`.

Only app-owned identifiers use the Talago name ([0002](./0002-talago-package-scope.md)).

## Consequences

- Searching the repo for "anvia" always returns these hits; they are expected.
- Renaming any of them breaks dependency install, the streaming styles, or the generated Prisma block.
- When porting a change from `anvia-fullstack-app`, carry the framework references across unchanged and rename only app-owned identifiers.
